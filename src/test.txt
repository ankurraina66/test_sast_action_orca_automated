Pull Request Summary Generation

Background

The existing implementation generated identical summaries for Push and Pull Request workflows. Reviewers could not identify the associated Pull Request, repository branch, or commit directly from the generated summary.

Support was added to enrich summaries generated during Pull Request executions.

Files Modified:

main.js

asoc.js

Technical Implementation

PR context is determined at the start of the workflow in main.js.

Actual Code

const isPR =

    process.env.INPUT_IS_PR_SCAN === "true" ||

    process.env.GITHUB_EVENT_NAME === "pull_request";

The workflow captures PR metadata.

const prNumber = process.env.INPUT_PR_NUMBER || "";

const branchName =

    process.env.INPUT_BRANCH_NAME ||

    process.env.GITHUB_HEAD_REF ||

    process.env.GITHUB_REF_NAME ||

    "";

const repoName =

    process.env.INPUT_REPO_NAME ||

    process.env.GITHUB_REPOSITORY ||

    "";

const commitSha = process.env.GITHUB_SHA || "";

The metadata is later propagated using

const githubContext = getGitHubContext();

resolve({ total, counts, issues: [], scanId, scanUrl, appName, appUrl, scanTime,   scanType, ...githubContext });

Finally, the markdown is generated through

writeSummaryMarkdown(summaryData, reportDownloadLink);
