Claude Code — Remote HTTP MCP Validation

MCP server: "hcl-appscan-ai-coding-assistants"
Provider: Remote HTTP
Purpose: Validate Remote HTTP connectivity, backend tool discovery, read-only AppScan operations, issue retrieval and provider switching.

Step 1 — Switch to Remote HTTP

Use only the "hcl-appscan-ai-coding-assistants" MCP server.

Call "switch-provider" with provider set to "remote".

Report:

1. Whether the Remote HTTP connection succeeded.
2. Whether backend tool discovery succeeded.
3. The number of discovered backend tools.
4. Any connection or authentication error.

Confirm that the active provider is remote.

Do not create or modify any AppScan resources.

---

STEP 2 — Verify Applications and Scans

Use only the "hcl-appscan-ai-coding-assistants" MCP server.

Confirm the active provider using "get-provider-status". It must be remote.

Perform these read-only operations:

1. Call "get-apps" and report the number of applications returned.
2. Call "get-scans" without filters and report the number of scans returned.
3. Report any errors encountered.

Do not create, update, or delete any AppScan resources.

---

STEP 4 — Retrieve Details for an Existing Issue

Use only the "hcl-appscan-ai-coding-assistants" MCP server.

Use the Remote HTTP provider.

STEP 5 — Switch Back to Local STDIO

Use only the "hcl-appscan-ai-coding-assistants" MCP server.

Call "switch-provider" with provider set to "local".

Report:

1. Whether the Local STDIO connection succeeded.
2. Whether backend tool discovery succeeded.
3. Number of discovered backend tools.
4. Whether any connection or authentication error occurred.

Confirm that the active provider is local.

Do not create or modify any AppScan resources.
