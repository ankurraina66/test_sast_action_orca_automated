---------------------------------------------------------------------------------------------------------
Customer Objective / Use Case:
The customer wants to perform a rescan (reuse an existing SAST and SCA scan) from their GitHub Actions pipeline, instead of creating a new scan every time.

They are using the official HCL AppScan SAST GitHub Action (HCL-TECH-SOFTWARE/appscan-sast-action@v1.1.0) and providing the existing scan IDs as documented in the action README:

sast_scan_id: 13e89553-4bd5-46d2-b67e-ce9b2bb447ad
sca_scan_id: 1162c5dd-fd33-484e-b3f3-c828d2b163b2

Expected behavior:
When sast_scan_id and sca_scan_id are supplied, the action should trigger a rescan (new execution on the existing scans) in AppScan on Cloud.

Actual behavior (Deviation):
The action is not performing a rescan. Instead, it creates a brand-new scan every time, ignoring the provided scan IDs.

Additional observation:
In some pipeline runs, the action also fails during IRX generation with the error:
Error: spawn EINVAL
