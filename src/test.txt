Proposed Approach: Enhance GitHub Pull Request Comments with PR Scan Summary

Background

The current GitHub Action generates scan summaries as part of the GitHub Step Summary, allowing users to review scan results directly from the workflow execution.

To improve the Pull Request review experience, I am evaluating an enhancement to surface the scan summary directly within the Pull Request conversation. This would allow reviewers to view the scan outcome without navigating to the workflow run.

Proposed Solution

The proposal is to automatically publish an AppScan scan summary as a comment on the Pull Request whenever the workflow is executed for a PR.

To avoid multiple AppScan comments accumulating over successive workflow executions, the solution would ensure that only a single AppScan-generated comment is maintained on the Pull Request. Each new workflow execution would refresh the existing summary so that reviewers always see the latest scan results.

High-Level Design

The proposed implementation would include the following components:

1. Introduce a dedicated PR Comment management component

A separate module would be introduced to encapsulate all GitHub Pull Request comment operations.

Responsibilities would include:

Publishing scan summary comments to Pull Requests.

Identifying previously generated AppScan comments.

Removing outdated AppScan comments before publishing an updated summary.

Isolating GitHub API interactions from summary generation logic.

This separation keeps summary generation independent from comment lifecycle management.

2. Separate summary generation from publishing

The existing summary generation logic would be refactored so that markdown generation is independent of where the content is published.

The generated markdown can then be reused for multiple destinations, including:

GitHub Step Summary

Pull Request comments

This approach avoids maintaining multiple implementations for the same summary content.

3. Support a consolidated PR comment

When multiple scan types (for example, SAST and SCA) are executed within the same workflow, the proposal is to publish a single consolidated Pull Request comment rather than multiple independent comments.

The consolidated comment would contain:

Pull Request information

SAST scan summary (if available)

SCA scan summary (if available)

This provides reviewers with a single location to view all scan results while reducing comment noise.

4. Preserve existing GitHub Step Summary behaviour

The enhancement is intended only for Pull Request comments.

The existing GitHub Step Summary functionality would remain unchanged so that current workflow behaviour is preserved for both PR and non-PR executions.

5. Handle multiple workflow executions

Since Pull Request workflows may execute multiple times during the lifetime of a PR, the proposal includes replacing the previous AppScan comment instead of creating additional comments.

Expected behaviour:

First PR execution creates an AppScan summary comment.

Subsequent executions remove the previous AppScan summary comment.

A new comment containing the latest scan results is published.

This ensures the Pull Request always displays the most recent security results while avoiding duplicate comments.

Files Expected to be Updated

The current implementation is expected to require changes in the following areas:

Summary generation component

Refactor markdown generation for reuse across multiple output destinations.

Support generation of a consolidated PR summary.

Result processing workflow

Capture generated summaries.

Coordinate publication once scan processing is complete.

Workflow execution logic

Support scenarios where scan results are immediately available as well as asynchronous scan execution.

New PR Comment management component

Handle GitHub Pull Request comment lifecycle.

Manage creation, replacement and cleanup of AppScan-generated comments.

Expected Benefits

Makes scan results immediately visible during Pull Request review.

Eliminates the need to navigate to workflow logs to review scan status.

Maintains a single up-to-date AppScan comment on the Pull Request.

Avoids duplicate comments across multiple workflow executions.

Reuses existing summary generation logic, minimizing duplication.

Preserves current Step Summary behaviour and backward compatibility.

Validation Plan

The proposed implementation will be validated against the following scenarios:

Pull Request workflows with SAST only.

Pull Request workflows with SCA only.

Pull Request workflows with both SAST and SCA.

Multiple executions against the same Pull Request.
